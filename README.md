# seg7-vision-reader

用一台**全局快门黑白 UVC 工业相机**，非接触读取 3 位数码管上显示的数字（0–100），用于电池放电测试中的电量记录。

配套完整方案文档：[`数码管视觉采集落地方案.html`](数码管视觉采集落地方案.html)（14 节，含参数表、标定流程、判读算法、故障排查、实测记录）

---

## 为什么不是「拍张照 + OCR」

这块屏是**动态扫描**驱动的：三位数字不是同时亮的，而是 GRID1 → GRID2 → GRID3 轮流导通，靠人眼余晖看成「同时亮」。所以难点不是清晰度，而是**曝光窗口有没有覆盖完整的刷新周期**——曝光短于刷新周期，一帧里就只拍到一位，另外两位是黑的。

通用 OCR 在这里也走不通：数码管字体和训练集里的字体对不上，过曝又会让笔画粘连，很容易把 `1` 认成 `7`。

本项目的做法是**按段判读**：对每一位数字的每一段单独取平均灰度，与阈值比较得出段码，再查表映射。

## 识别空间只有 101 种

这块屏的最左位是**半位**，只有 b、c 两段，物理上不可能显示 0。因此：

| 位 | 可显示状态 | 状态数 |
|---|---|---|
| 左位（半位） | 空白 / 1 | 2 |
| 中位（十位） | 0–9，**0–9 时消隐** | 10（或空白） |
| 右位（个位） | 0–9 | 10 |
| **合计合法取值** | **0 – 100** | **101 种** |

而三位的原始状态空间是 2 × 11 × 10 = **220 种**。**超过一半（约 54%）的组合在物理上不可能出现**——任何一次误判都有很高概率落进这个「不可能区」被当场逮住。这比后端加置信度打分可靠得多，是准确率的主要来源。

判据总数只有 **16 个是非题**（左位 2 段 + 中位 7 段 + 右位 7 段）。

## 硬件与场景前提

- **相机**：杰锐微通 DCXG100，1280×720 / 全局快门 / 黑白 / UVC 免驱
- **被测物静止**、**只能拍照**（不可接触、不可接线）
- 一帧读全部 3 位
- 黑白是加分项：省掉去马赛克、感光效率更高，配窄带蓝光滤光片后画面接近二值图

## 安装

```powershell
pip install opencv-python numpy
```

## 快速开始

**推荐执行顺序：`snap` → `selftest` → `probe` → `calib` → `read`**
（相机没反应就先插一步 `diagnose` 定位问题，别在错误的方向上调参数）

```powershell
# 0) 不带参数会打印推荐执行顺序
py seg7_reader.py

# 1) 抓一张图，先生看看相机拍到了什么
py seg7_reader.py snap

# 2) 不接相机，用合成图像验证整条判读链路（17 项自检）
py seg7_reader.py selftest

# 3) 看当前画面亮度，判断该不该减光
py seg7_reader.py probe

# 4) 交互框选三个数字的外接矩形，生成 ROI 模板
py seg7_reader.py calib

# 5) 日常读数
py seg7_reader.py read --template seg7_roi.json
```

### 周期性采集（记录放电曲线）

```powershell
# 每 60 秒采一次，写进 CSV，读到 100 或 0 连续 5 次就自动收工
py seg7_reader.py read --template seg7_roi.json --every 60 `
    --csv battery_log.csv --stop-at 100 0

# 每 5 分钟一次，跑满 12 轮（1 小时）就停
py seg7_reader.py read --template seg7_roi.json --every 5m --count 12 --csv log.csv
```

要点：

- `--every` 支持 `60` / `60s` / `1m` / `5m` / `2h`；**设了它自动持续运行，不用再加 `--watch`**
- 节奏是**严格间隔**：睡「间隔 − 本轮耗时」，不会因为采集本身要花几秒而越跑越慢
- 相机全程**只打开一次**，避免反复开关（这个驱动对反复开关很敏感）
- `--stop-at` 的命中判定：失败轮次**既不计入、也不重置**已累计的连续次数（失败 = 没读到，不代表值变了）

运行输出：

```
[周期] 每 60 秒一次，Ctrl+C 停止
[终止] 连续 5 次读到 0 或 100 时自动结束
[日志] 追加写入 ...\battery_log.csv
[读数]  13（原始 '13'）连续一致 3/3 ｜ 命中 13: 1/5
```

## 六种模式

| 模式 | 作用 |
|---|---|
| `snap` | 抓一帧存成图片，先看看相机拍到了什么 |
| `diagnose` | 枚举相机设备、报告图像统计、隔离测试哪个属性写入会破坏画面 |
| `selftest` | 不接相机，用合成图像验证整条判读链路 |
| `probe` | 报告当前画面亮度统计（不需要模板），判断该不该减光 |
| `calib` | 交互框选三个数字的外接矩形，自动切成各段 ROI，生成模板 JSON |
| `read` | 按模板采集并输出读数（默认连续多帧一致才输出） |

### 常用参数

| 参数 | 说明 |
|---|---|
| `--camera N` | 设备序号，默认 0 |
| `--template PATH` | ROI 模板 JSON，默认 `seg7_roi.json` |
| `--frames N` | 融合帧数（默认 3） |
| `--fusion mean\|max` | 融合方式，**默认 mean** |
| `--agree N` | 连续几帧读数一致才输出，默认 3 |
| `--every VAL` | 周期采集间隔，设了自动持续运行 |
| `--csv PATH` | 每轮追加一行「时间,电量」，自动写表头 |
| `--stop-at V...` | 连续读到这些值就终止，例如 `--stop-at 100 0` |
| `--stop-streak N` | 需要连续命中几次才终止，默认 5 |
| `--count N` | 跑满 N 轮后退出，0 = 不限 |
| `--debug` | 打印每段实测灰度明细 |
| `--save-debug PATH` | 把标注图存到指定路径 |

## 踩过的坑（都是真机上定位的）

这几条是这套方案能跑通的关键，改动前务必先读：

### 1. 写曝光属性会把画面变成纯白 —— 所以默认不写

实测：只要写 `AUTO_EXPOSURE` / `EXPOSURE` 这两个属性，画面立刻变成 **`std = 0`、`min = max = 254`** 的纯色。这是驱动不接受 OpenCV 这种写法，**不是相机坏了**。

因此工具**默认完全不写曝光/增益属性**，改用相机自身的自动曝光。只有显式加 `--exposure-write` 才会去写。

> **怎么区分「驱动写坏」和「真的过曝」**：看 `std`。过曝的图有层次、只是亮部没细节（`std` 正常）；驱动写坏是整幅一个值（`std ≈ 0`）。看到纯色先看 `std`，别急着调光学。

### 2. 融合方式必须用 mean，不能用 max

灭段自己不发光，它收到的是**亮段的散射光**。散射光的积分量正比于「亮段导通时间落在曝光窗口内的比例」，曝光窗口每次落点不同，这个比例就变，灭段灰度就跳（实测偶发从 0 跳到 80–160）。

`max` 逐像素取最大值，**帧数越多越容易逮到那次跳变并把它保留下来**，是失败的放大器：

| 配置 | 成功率 |
|---|---|
| `--fusion max --frames 3` | 33%（9 次丢 6 次） |
| `--fusion mean --frames 3` | **100%（attempts = 2，零丢弃）** |

要越阈值需要 8 帧里 3 帧以上同时跳变，基本不会发生。所以 **mean 模式下加帧数是纯收益，max 模式下加帧数是纯损失**。

### 3. 这块屏电量掉到 1 之后不会显示 0

实测（`--every 60`，每分钟一次）：`11 → 11 → 10 → … → 2 → 1 →` **直接变成空值（屏灭了）**，
**全程没出现过 0**，放电速率约 1 %/分钟。

所以 `--stop-at 0` 对放电测试**没有用**——会一直跑到设备关机、CSV 里全是空行。真正的放电终点信号是「屏灭」。

### 4. 分辨率裕量目前不足（已知项，待改进）

实测笔画宽只有 **8–9 px**，段采样区约 130 px²，段采样框只要偏 8 px（占画面宽 0.6%）就会落到段间空隙里导致误判。

| | 现在 | 目标 |
|---|---|---|
| 笔画宽 | 8–9 px | ≥ 20 px |
| 字高占画面高度 | 10% | ~25% |

解法是换一支 **8mm 左右的镜头**（当前装的应是最广的 2.1/2.8mm 档），把视野放大 2.5–3 倍。**不要靠缩短工作距离**——那会带来四角压暗和边缘变形。

### 5. 中位在 0–9 时是消隐的

即 5 会显示成 `  5` 而不是 `005`，只有在 100 时才显示 0。由此可得一条白拿的校验规则：**非 100 情况下读出「十位 = 0」应直接判为误读并丢弃**。
